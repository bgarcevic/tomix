# tx
tx - inspect, validate, query, test, and deploy tabular semantic models
  opt --help, -?, -h, /?, /h  Show help and usage information
  opt --version  Show version information
  opt --model, -m <model>  Path to the semantic model: a TMDL folder, a .bim file, or a model folder
  opt --output-format <output-format>  Format for data written to stdout: text (default), json, csv, tmsl (alias: bim), or tmdl. Availability varies by command.
  opt --error-format <error-format>  Format for messages written to stderr: text (default) or json. Unrecognized values fall back to text.
  opt --server, -s <server>  Workspace to connect to: a name, a powerbi:// or asazure:// endpoint, or a local address
  opt --database, -d <database>  Name of the semantic model to use on the workspace
  opt --auth <auth>  How to authenticate: auto, interactive, spn, or managed-identity (default: auto)
  opt --recent, --recents <recent>  Pick a model from the recently used list: no value opens a picker, a number picks that entry (1 is the most recent).
  opt --debug  Show the full stack trace on stderr when an unexpected error occurs
  opt --non-interactive  Never prompt for input. When required input is missing, fail with an error saying what to provide.
  opt --yes, -y  Skip confirmation prompts for destructive operations
  opt --quiet, -q  Suppress non-essential output (spinners, progress, hints). Errors and data still print.

# tx add
Create a new object in the model
  arg <path>  Where to create the object, slash-separated: 'Sales/Revenue', 'Products', 'Admin'. DAX form also accepted: "'Sales'[Revenue]". Combine with -t. For relationships, use 'Sales[Key]->Product[Key]' (many side first).
  arg [model]  Optional path to the model; defaults to the active connection
  opt --type, -t <type>  Type of object to create. Supported values: Table, CalcTable, CalcGroup, Measure, CalcColumn, DataColumn, Hierarchy, Level, Calendar, CalcItem, KPI, Partition, MPartition, EntityPartition, PolicyRangePartition, Expression, Function, Perspective, Culture, ProviderDataSource, StructuredDataSource, Role, TablePermission, Member, Relationship. Data sources always require -t (no path keyword infers them).
  opt -i <i>  Compatibility form of --expression / --set: an unpaired -i is the new object's value; pair each -q with a following -i to set a property. Use '-' to read from stdin.
  opt -q <q>  Compatibility form of --set: property name to set on the newly-created object; pair each -q with a following -i value. Repeatable.
  opt --expression, -e <expression>  Expression or value for the new object. Use '-' to read from stdin.
  opt --set <set>  Set a property on the new object: name=value, e.g. --set formatString="#,0". Repeatable. Names can use dotted paths, bracket indexers, or a DisplayName.
  opt --file <file>  Read the expression from this file
  opt --if-not-exists  Do nothing and exit 0 when the object already exists
  opt --force, -f  Save despite newly introduced validation errors
  opt --overwrite  Allow --save-to to overwrite an existing target
  opt --dry-run  Preview: show the change without saving, staging, or syncing
  opt --save-to <save-to>  Write the saved model to this path instead of its source (implies --save)
  opt --serialization <serialization>  How the model is written: tmdl or bim (tmsl and auto also accepted)
  opt --save  Write this command's change back to the model's source. Cannot be combined with --revert or --stage.
  opt --stage  Stage this command's mutation
  opt --revert  Revert a staged mutation
  opt --no-sync  Skip workspace sync when workspace mode is active.
  opt --mode <mode>  Storage mode for the partition: Import, DirectQuery, Dual, DirectLake, Push, or Default.
  opt --source <source>  Provider name for a ProviderDataSource (e.g. System.Data.SqlClient).
  opt --endpoint <endpoint>  Server/endpoint address for a data source connection.
  opt --connection-string <connection-string>  The connection string used by a ProviderDataSource.
  opt --source-table <source-table>  Source entity/table name for an EntityPartition.
  opt --source-database <source-database>  Source database name for a data source connection (Provider/Structured data sources).
  opt --source-schema <source-schema>  Source schema name for an EntityPartition.
  opt --partition-expression <partition-expression>  The M or DAX expression defining the partition's source.
  opt --columns <columns>  Comma-separated column names to create on a new table (Table type only).
  opt --source-type <source-type>  Connection protocol for a StructuredDataSource (e.g. tds).
  opt --range-start <range-start>  Refresh-policy range start for a PolicyRangePartition (yyyy-MM-dd).
  opt --range-end <range-end>  Refresh-policy range end for a PolicyRangePartition (yyyy-MM-dd).
  opt --range-granularity <range-granularity>  Refresh-policy range granularity for a PolicyRangePartition: Day (default), Month, Quarter, Year.

# tx connect
Set active connection (workspace, local path, or PBI Desktop). No args = show current. --recent = reconnect to a recently used model.
  arg [server]  Workspace name, endpoint, or local model path; combine with --local for Power BI Desktop.
  arg [database]  Semantic model name (omit on a TTY to pick from the workspace's models).
  opt --workspace, -w <workspace>  Enable workspace mode: mirror saves between the primary source and a secondary target. Primary remote -> pass a local folder or .bim file. Primary local -> pass <server> <database>. Pass -w with no value to pick the target workspace and model interactively.
  opt --local  Attach to a Power BI Desktop instance running on this machine (Windows only)
  opt --remote  Pick a workspace and semantic model interactively from your Power BI tenant (requires a TTY; sign in first with 'tx auth login').
  opt --profile, -p <profile>  Connect through this saved profile (list them with 'tx profile list')
  opt --clear  Forget the active connection
  opt --force  Allow workspace mode to initialize over a folder that already has content.
  opt --workspace-format <workspace-format>  How a local workspace is stored on disk (tmdl or bim); detected from the path when omitted.
  opt --workspace-auth <workspace-auth>  How to authenticate the remote side of workspace mode. Defaults to --auth when set, otherwise auto.

# tx deploy
Deploy a semantic model to a workspace
  arg [model]  Optional path to the model to deploy; defaults to the active connection
  opt --profile, -p <profile>  Deploy through a saved profile for this run only; see 'tx profile list' and 'tx profile set'
  opt --create-only  Create the target model only if it does not exist yet; fail when it does
  opt --xmla <xmla>  Write the deployment as a TMSL script to this file instead of deploying. Pass '-' to write to stdout.
  opt --skip-bpa  Skip the BPA gate check for this deploy.
  opt --fix-bpa  Apply BPA rule fixes to the model before deploying, where a rule provides one
  opt --bpa-rules <bpa-rules>  Additional BPA rule files to enforce for this deploy, alongside the built-in ruleset.
  opt --bpa-fail-on <bpa-fail-on>  Severity threshold for the BPA gate: error (default) or warning. Applies before the deploy and again after --fix-bpa fixes. Rules that cannot be evaluated count as error-severity findings
  opt --force  Force deployment, bypassing validation checks
  opt --ci <ci>  Print CI log-group commands to stderr for the given system: vsts or github
  opt --dry-run  Preview what would change on the remote target without deploying
  opt --deploy-connections  Overwrite the target's data sources (default: keep the target's connection strings)
  opt --deploy-partitions  Overwrite the target's table partitions (default: keep the target's partitions and processed data)
  opt --deploy-policy-partitions  With --deploy-partitions: also overwrite incremental-refresh policy partitions, discarding processed data (default: keep them)
  opt --deploy-shared-expressions  Overwrite the target's shared expressions / M parameters (default: keep the target's values)
  opt --deploy-roles  Overwrite the target's security roles (default: keep the target's roles)
  opt --deploy-role-members  With --deploy-roles: also overwrite role members (default: keep the target's members)
  opt --deploy-full  Overwrite everything, including incremental-refresh partitions (cannot be combined with other --deploy-* flags)

# tx set
Change a property on a model object
  arg <path>  The object to change, slash-separated. DAX form works too.
  arg [model]  Optional path to the model; defaults to the active connection
  opt -q <q>  Compatibility form of --set: the property to set; give its value with -i.
  opt -i <i>  Value for the preceding -q. Pass '-' to read from stdin.
  opt --set, -p <set>  Property assignment as name=value. Repeat to set multiple properties together.
  opt --force, -f  Save despite newly introduced validation errors
  opt --overwrite  Allow --save-to to overwrite an existing target
  opt --dry-run  Preview: show the change without saving, staging, or syncing
  opt --type, -t <type>  Disambiguate when the path matches multiple objects (e.g. a measure and a partition sharing a name).
  opt --save  Write this command's change back to the model's source. Cannot be combined with --revert or --stage.
  opt --save-to <save-to>  Write the saved model to this path instead of its source (implies --save)
  opt --serialization <serialization>  How the model is written: tmdl or bim (tmsl and auto also accepted)
  opt --stage  Stage this command's mutation
  opt --revert  Revert a staged mutation
  opt --no-sync  Skip workspace sync when workspace mode is active.
  opt --strict-refs  Fail when a rename leaves DAX references broken (with fixup on, only unfixable references fail).
  opt --no-fix-refs  Do not rewrite DAX references to the renamed object; warn instead.

# tx stage
Inspect and manage staged (uncommitted) model mutations

# tx stage status
Show staged mutations for the active model

# tx stage list
List all staged models in the current session

# tx stage discard
Discard staged mutations without committing them
  opt --all  Discard staged mutations for every model in the session, not just the active one

# tx stage commit
Promote staged mutations onto the source (and workspace mirror)
  opt --force  Commit despite source drift and newly introduced validation errors.

# tx test
Run DAX regression tests against a live model (--update records snapshots, --trx/--ci for pipelines)
  arg [path]  Test file or directory searched recursively for .dax tests (default: current directory)
  opt --update  Record mode: run each query and (re)write its .expected.json snapshot from the actual result.
  opt --filter <filter>  Run only tests whose name matches a * wildcard pattern (case-insensitive).
  opt --param <param>  Query parameter as name=value, referenced as @name in DAX. Applied to every test. Repeatable.
  opt --max-rows <max-rows>  Per-query row cap; a query exceeding it fails as an error (default: 10000).
  opt --ci <ci>  Print CI log-group commands to stderr for the given system: vsts or github
  opt --trx <trx>  Write results to a .trx test-run file at this path

# tx update
Update tx to the latest release.
  opt --check  Preview only: show the latest version and release notes without changing anything.
  opt --version <version>  Update (or downgrade, with --yes) to a specific released version instead of the latest.
  opt --output-format <output-format>  Format for data written to stdout: text (default), json, csv, tmsl (alias: bim), or tmdl. Availability varies by command.

# tx validate
Check a model's DAX expressions and relationship integrity (--ci for CI output, --trx for test results)
  arg [model]  Optional path to the model; defaults to the active connection
  opt --ci <ci>  Print CI log-group commands to stderr for the given system: vsts or github
  opt --trx <trx>  Write results to a .trx test-run file at this path
  opt --errors-only  Only show errors
  opt --no-warnings  Leave out analyzer warnings
  opt --no-multiline  Show multi-line cell content on one line. Applies to text output.
  opt --server-only  Only show errors reported by the connected server

# tx vertipaq
Report VertiPaq storage statistics for a semantic model
  arg [table]  Table name to filter the analysis to a single table
  opt --tables  Show the tables view
  opt --columns  Show the columns view (default)
  opt --relationships  Show the relationships view
  opt --partitions  Show the partitions view
  opt --all  Include the tables, columns, relationships, and partitions views
  opt --detail  Extra columns: data/dictionary/hierarchy size breakdown, encoding, segments
  opt --fields <fields>  Comma-separated fields to display (e.g. name,card,size,%tbl,%db,bar). Available fields vary by view; requires a single view. Text and csv output only.
  opt --top <top>  Limit each view to the N largest rows. Text and csv output only.
  opt --stats  Show a model-level storage summary (combine with view flags for more)
  opt --annotate  Write statistics into the model as Vertipaq_* annotations (preview unless --save)
  opt --save  Persist --annotate changes to the model
  opt --force, -f  Save despite newly introduced validation errors
  opt --export <export>  Export statistics to a .vpax file for offline analysis
  opt --import <import>  Analyze a previously exported .vpax file offline (no connection needed)
  opt --obfuscate  Mask names and expressions in the exported .vpax; a matching .dict dictionary keeps the mapping private
